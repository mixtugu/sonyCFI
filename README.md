# 사이의 길 · Between Paths

**Cloudflare Workers 배포:** https://sony-cfi-between-paths.timmy0079.workers.dev

공개 주소에서 일본어 미로 게임을 2명이 동시에 플레이할 수 있습니다. 재배포는 `npm run deploy`, Workers 로컬 실행은 `npm run worker:dev`입니다. 자세한 내용은 [WORKERS.md](WORKERS.md)를 참고하세요.

기본 게임을 `test_coding`의 파이썬 게임을 참고한 **부모·아이 두 시점의 미로 게임**으로 개편했습니다. `npm run dev` 실행 후 `http://localhost:5173`에서 바로 플레이할 수 있습니다. 부모/아이/CPU 모드, 벽과 비밀 통로, 점수, 미로·시간·아이템 설정을 지원합니다.

새 미로도 **두 사람이 각자 브라우저에서 동시에 플레이**할 수 있습니다. 화면 위에서 방을 만들고 초대 링크 또는 코드를 공유한 뒤, 두 사람 모두 준비 완료를 누르세요. 부모는 벽을 설치하고 아이는 이동하며, 역할별 화면과 비밀 통로가 분리됩니다. 방에 들어가지 않으면 CPU와 혼자 연습할 수 있습니다.

새 게임의 조작법과 검증 방법은 [MAZE.md](MAZE.md)를 참고하세요. 기존 온라인 게임은 `/?online=1`과 기존 초대 링크에서 이용할 수 있습니다. 아래 내용은 기존 온라인 모드의 안내입니다.

# 둘 사이의 바다 · Between Tides

각자 다른 브라우저에서 같은 방에 접속해, 아이는 헤엄치고 부모는 실시간으로 벽을 설치하는 2인용 게임입니다. 화면, 목표, 지도 정보, 조작법이 역할별로 나뉘어 있습니다. UI는 일본어로 제공됩니다.

## 실행

Node.js 20.19 이상 또는 22.12 이상을 사용합니다.

```sh
npm install
npm run dev
```

PC에서 `http://localhost:5173`을 엽니다. 한 사람이 역할을 선택해 방을 만들고, 다른 사람은 별도의 브라우저나 기기에서 6자리 방 코드 또는 초대 링크로 참가하세요. 두 사람 모두 준비를 마치면 3초 카운트다운 후 게임이 시작됩니다.

같은 Wi-Fi에 연결된 스마트폰이나 PC에서 접속하려면, 실행할 때 표시되는 `http://<PC의 LAN 주소>:5173`을 여세요. localhost에서 방을 만들면 개발 서버가 감지한 LAN 주소를 초대 링크에 사용합니다. 네트워크 어댑터가 여러 개라면 실행 로그에서 실제로 공유 중인 네트워크 주소를 선택하세요. 방 코드만으로는 서로 다른 서버끼리 연결할 수 없습니다.

Windows PC에 다른 기기에서 접속할 수 없다면 두 기기가 같은 네트워크에 연결되어 있는지, Node.js 로컬 서버가 개인 네트워크 방화벽에서 허용되어 있는지 확인하세요. 이 프로젝트는 운영체제 설정을 변경하지 않습니다.

## 역할별 화면

| 구분 | 아이: 작은 탐험가 | 부모: 바다의 보호자 |
| --- | --- | --- |
| 나만의 목표 | 진주 5개를 모아 동쪽의 빛의 문으로 이동 | 아이를 서쪽의 조용한 만에 총 25초 동안 머물게 하기 |
| 나에게만 보이는 요소 | 진주, 빛의 문, 내 진행 상황 | 조용한 만, 체류 시간 |
| 공통으로 보이는 요소 | 탐험가, 설치된 벽, 남은 시간 | 탐험가, 설치된 벽, 남은 시간 |
| 조작 | WASD·방향키·화면 조이스틱 | 드래그로 벽 설치, 클릭으로 기본 벽 설치. WASD·방향키·IJKL로 조준, Space로 설치, R로 회전 |
| 게임패드 | 해당 기기의 첫 번째 게임패드: 왼쪽 스틱 | 해당 기기의 첫 번째 게임패드: 왼쪽 스틱, A/×로 설치, X/□로 회전 |

부모는 아이 캐릭터를 직접 움직일 수 없고, 아이는 벽을 설치할 수 없습니다. 이 제한은 UI뿐 아니라 서버에서도 검증합니다. 상대방의 임무, 진행 상황, 전용 지도는 게임이 끝나기 전까지 해당 역할이 아닌 소켓으로 전송하지 않습니다.

터치 기기에서는 부모도 조이스틱으로 조준하고 「벽 설치」 버튼을 눌러 조작할 수 있습니다. 게임패드는 표준 매핑을 사용하며 localhost 또는 HTTPS 환경에서 작동합니다. LAN의 HTTP 연결에서는 터치나 키보드를 사용하세요. 실제 게임패드의 기종별 동작은 아직 확인하지 않았습니다.

## 규칙과 돌아보기

- 항해 시간은 90초입니다. 아이가 목표를 달성하면 즉시 종료됩니다.
- 벽의 최대 길이는 월드 좌표 기준 180이며 12초 동안 유지되고, 최대 5개까지 설치할 수 있습니다. 설치 간격은 0.65초입니다. 여섯 번째 벽을 설치하면 가장 오래된 벽이 사라집니다.
- 아이 캐릭터 위에는 벽을 설치할 수 없습니다. 벽에 닿으면 이동이 멈추며, 우회하거나 1.4초 동안 계속 밀면 넘어갈 수 있습니다.
- Esc 또는 「잠시 쉬기」를 누르면 양쪽 모두 일시 정지됩니다. 브라우저 탭을 숨겨도 일시 정지됩니다.
- 연결 끊김을 감지하면 양쪽 모두 일시 정지됩니다. 새로고침하거나 잠시 연결이 끊긴 뒤에는 같은 화면의 세션 토큰으로 기존 역할에 복귀하며, 두 사람이 준비하면 다시 시작합니다. 이동 입력은 250ms 후 만료되므로 통신이 끊겨도 계속 헤엄치지 않습니다.
- 일시 정지 중 「지금까지의 항해 돌아보기」를 선택하면 양쪽 화면에서 게임이 종료됩니다. 목표, 실제 이동 경로, 벽의 기록, 벽 앞에 머문 시간을 공개합니다.
- 리플레이 슬라이더는 각자 화면에서 자유롭게 조작할 수 있습니다. 역할 교대에는 두 사람의 동의가 필요하며, 같은 연결을 유지한 채 역할과 조작법이 바뀝니다.

각 수치는 게임의 초기 밸런스 값입니다. 좋은 부모나 좋은 아이를 평가하는 기준이 아니라, 상대방의 의도를 이야기하는 계기로 사용합니다.

## 연결 구조

- `server/index.js`: HTTP와 WebSocket을 같은 포트에서 제공합니다. 개발 환경에서는 Vite 미들웨어를 사용하고, 운영 환경에서는 `dist`를 제공합니다.
- `server/rooms.js`: 방, 역할별 토큰, 참가 인원, 준비 상태, 재연결, 역할별 정보 공개 범위를 관리합니다.
- `src/game.js`: 이동, 벽, 충돌, 타이머를 서버에서 30Hz로 계산합니다. 클라이언트는 입력만 전송하고, 수신한 위치를 보간해 그립니다.
- `src/main.js`: 일본어 UI, 방 연결, 각 기기의 입력, 연결 복구를 담당합니다.
- `src/renderer.js`: 역할별 Canvas 화면과 기록 리플레이를 그립니다.

방과 기록은 서버 메모리에 저장되므로 서버를 재시작하면 사라집니다. 두 사람의 연결이 모두 끊긴 상태로 2분이 지나면 방을 삭제합니다. 계정, 영구 저장, 관전 모드는 지원하지 않으며 방마다 최대 2명이 참가할 수 있습니다.

## 운영 환경 실행 및 외부 네트워크 접속

```sh
npm run build
npm start
```

`npm run preview`도 같은 운영 서버를 실행합니다. 포트는 `PORT` 환경 변수로 변경할 수 있습니다.

서로 다른 Wi-Fi나 인터넷을 통해 플레이하려면 Node.js를 실행할 수 있는 호스트에 배포하고, HTTPS와 `/socket`의 WebSocket Upgrade를 전달하도록 설정하세요. 정적 파일만 제공해서는 방을 연결할 수 없습니다. 현재 외부 배포와 여러 서버 사이의 방 공유는 구현되어 있지 않습니다.

## 검증

```sh
npm test
npm run build
```

게임의 충돌, 이동, 종료뿐 아니라 역할 제한, 비공개 정보 분리, 두 사람의 준비 상태, 연결 끊김과 복귀, 역할 교대, 실제 WebSocket 통신을 검증합니다.

개발 서버를 실행한 뒤 서로 독립된 브라우저 사이의 시나리오를 실행합니다.

```sh
npx playwright install chromium
node scripts/check-browser.mjs
```

방 참가, 세 번째 참가자 거부, 위치와 벽 동기화, 새로고침 후 복귀, 각 기기의 가상 게임패드, 공동 돌아보기, 역할 교대, 스마트폰 터치 조작을 확인합니다. 스크린샷은 `artifacts/*-ja.png`에 저장합니다.

게임패드 참고 자료: [MDN Gamepad API](https://developer.mozilla.org/en-US/docs/Web/API/Gamepad_API/Using_the_Gamepad_API). 서버 참고 자료: [ws](https://github.com/websockets/ws), [Vite 미들웨어 모드](https://vite.dev/config/server-options#server-middlewaremode).
